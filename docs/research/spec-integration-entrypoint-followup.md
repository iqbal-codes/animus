# Issue 56: pinned entrypoint and composition follow-up

## Decision boundary

**The pinned loader discovers the relevant primitives in one isolated source-mode configuration; it does not establish a supported end-to-end one-spec, one-PR workflow.** Neither deterministic child selection by the loop nor parent-wide integration serialization is demonstrated. Do not launch or implement this design on the strength of discovery. This extends `git show 41f7551:docs/research/spec-workflow-entrypoints.md`, not a replacement for its safety constraints or prior test results.

Factory revision `5fa30a37748d0acde86a6fc6c0fc3ba49d5e8105` pins Archon `5c4f5e484262185926b37b070457fabb9bfedae0` in [`factory/pack.json`](https://github.com/iqbal-codes/labq-software-factory/blob/5fa30a37748d0acde86a6fc6c0fc3ba49d5e8105/factory/pack.json#L1-L32). Factory's `.factory/consumer.json` is absent in this checkout; the host's [source lookup](https://github.com/iqbal-codes/labq-software-factory/blob/5fa30a37748d0acde86a6fc6c0fc3ba49d5e8105/apps/engine-host/src/native.ts#L25-L50) and pack pin identify the inspected cache. ## Evidence by seam

1. **Discovery, not permission or host API.** The loader supports project/global/bundled discovery and installed-pack entrypoints have separate manifest-qualified rules ([discovery](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/workflows/src/workflow-discovery.ts#L1-L21), [loader options](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/workflows/src/workflow-discovery.ts#L712-L745)). A fresh run captures workflow source separately from target checkout; runtime workflow children capture separately except installed packs ([source](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/workflows/src/workflow-source.ts#L1-L41)). The Factory host itself invokes `archon-loop`, not an arbitrary catalog entry ([launch](https://github.com/iqbal-codes/labq-software-factory/blob/5fa30a37748d0acde86a6fc6c0fc3ba49d5e8105/apps/engine-host/src/native.ts#L246-L311)). Loader discovery does not prove a supported public contract for directly invoking an internal `-block`, installed-pack availability, or actual dispatch with Factory's configuration.
2. **Child targeting.** `archon-loop` describes a board-wide agent pick; its declared inputs contain no child issue selector, and `claim` consumes the pick output ([loop](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/.archon/workflows/sdlc/loop/archon-loop.yaml#L1-L105)). A prompt naming an issue is not a deterministic selector. The claim arbitrates one selected item, not the parent integration branch. `archon-implement` accepts `work` or a trigger message and promises commits without PR, returning `green`; it does not declare an issue identity, claim or dependency gate ([definition](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/.archon/workflows/sdlc/implement/archon-implement.yaml#L1-L39)). Supplying a frozen child contract as work is an [INFERENCE] possible composition, not proof of deterministic issue ownership or correct implementation. Completed run is not sufficient: check authored `green`.
3. **Isolation and integration.** CLI supports isolated branch worktrees, `--from` and `--base`; on reuse `--from` is ignored and `--base` changes the PR target, not cut-from. Reused base validation is warning-only ([CLI](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/cli/src/cli.ts#L745-L825), [reuse](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/cli/src/commands/workflow.ts#L3043-L3112)). A fresh worktree is not an integration lock, and a branch name is not proof of its starting SHA. No examined public composition serializes approved child commits into a parent branch or resolves conflicts/recovery. `archon-deliver-block` includes implementation and review but also owns PR-oriented delivery ([composition](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/.archon/workflows/sdlc/deliver/archon-deliver-block.yaml#L100-L110)); that is not evidence for zero child PRs.
4. **Final candidate.** Review has `scope`, `work_order`, `part` and `ready`, checks matching PR head before its review nodes and may publish a canonical comment ([review](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/.archon/workflows/sdlc/review/archon-review-block.yaml#L1-L71), [head gate](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/.archon/workflows/sdlc/review/archon-review-block.yaml#L89-L100)). Runtime accepts a scenario and candidate, returning `verified` ([runtime](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/.archon/workflows/sdlc/verify-runtime/archon-verify-runtime.yaml#L1-L33)). These interfaces alone do not prove independent identities, complete parent-contract coverage, or that the deployed runtime corresponds to the tested merge tree. A PR head match alone does not bind a moving base.
5. **Final gate.** `archon-merge-queue` takes 1–5 explicit PR URLs, has preview/approve/auto, optional evidence and configurable required checks/protected paths; it computes CI and path facts and gates an assessment ([queue](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/.archon/workflows/sdlc/merge-queue/archon-merge-queue.yaml#L1-L174)). Optional evidence and default empty protected paths are not an enforced two-independent-parent-wide-evidence contract. `preview` is documented read-only; approve, auto, publication and merge remain separate authorities. Failed prior offline boundary tests are not evidence of merge safety.

## Safe offline loader probe

Ran the pinned cache at the revision above with pre-existing dependencies, a fresh temporary `HOME` and `ARCHON_HOME`, and `loadDefaults:false`, `loadDefaultCommands:false`, `sourceRoots:liveSourceRoots(process.cwd())`; called `discoverWorkflows` directly with `providerRegistry`. It returned project-source entries named `archon-loop`, `archon-implement`, `archon-review-block`, `archon-verify-runtime`, and `archon-merge-queue`. It also returned **21 validation errors** for other workflows naming unregistered providers and warned that an included deploy workflow's `mutates_checkout` field was dropped. The probe did not register providers, configure installed packs, run CLI dispatch, invoke nodes, or establish network-level isolation; the invoked loader is a local filesystem discovery operation. Its source was the existing pinned cache, not a copied fixture. An initial attempt against `/tmp/archon-research-56` failed to resolve workspace dependencies; no installation was attempted. No holdout contents, live workflow, real `gh`, tracker or product changes were involved.

## Open decisions and next safe work

- Authorize and define the meaning of one PR: one total, or child PRs allowed; designate graph snapshot, membership and dependency authority. Current admission requires closed dependencies and completed outcomes on the selected base ([factory contract](https://github.com/iqbal-codes/labq-software-factory/blob/5fa30a37748d0acde86a6fc6c0fc3ba49d5e8105/docs/agents/software-factory-workflow.md#L57-L90)); any alternate rule for still-open children needs approval.
- Decide who owns deterministic target verification, claims, branch lock/serialization, exact starting SHA, conflict handling, recovery and revalidation. A proposed external coordinator must be explicitly judged against the no-duplicate-scheduler constraint; no such authorization follows from this note.
- Establish final head H, destination base B, merge tree M and a trustworthy M-to-runtime mapping; require independent parent-wide runtime and code review and current required checks, then fail closed on absent, stale, mismatched or inconclusive evidence. Re-evaluate when H or B changes. Decide protected paths, environment ownership, holdout secrecy and teardown before execution.
- Confirm supported dispatch and composition with the actual configured provider registry and pack/source scopes using non-executing isolated tests; investigate earlier failed suites without suppressing errors. Separately authorize any workflow execution, PR creation, comment publication, deployment, approval or merge. This research does not close issue 56.
