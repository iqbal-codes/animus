# Research conclusion: native eligibility and evidence integrity

## Scope and verdict

[Investigate native eligibility and evidence integrity](https://github.com/iqbal-codes/labq-software-factory/issues/57) remains **unresolved** as a full research question: the existing native path has no demonstrated enforceable target-binding seam, and independent, current-candidate evidence provenance has not been established. The negative findings and fail-closed operating recommendation are sufficiently grounded to inform planning, but they do not prove a complete implementable solution. Implementation and any change to protected governance or workflows require separate authorization.

The parent [Arsitektur Web Console Software Factory](https://github.com/iqbal-codes/labq-software-factory/issues/46) specifies planning only, separate permissions for publication/admission/launch/approval/merge, GitHub and Archon as authorities, and no private workflow fork or weakened evaluator. Wayfinder classifies its map and decision tickets as planning records rather than executable tickets; a Wayfinder label is not an enforcement mechanism. The issue was open and assigned when read, with two comments explicitly calling earlier work unresolved. This document does not alter the tracker.

Factory source baseline: `5fa30a37748d0acde86a6fc6c0fc3ba49d5e8105`; pinned Archon: `5c4f5e484262185926b37b070457fabb9bfedae0` (`factory/pack.json`). Local pinned cache HEAD matched, with clean status. Detailed source analysis and prior test results are in the existing research-only commits [`cee4f9e:docs/research/eligibility-evidence.md`](https://github.com/iqbal-codes/labq-software-factory/blob/cee4f9e0b5b0142373587b8fd989b1f3499535a3/docs/research/eligibility-evidence.md) and [`4ec6e86:docs/research/eligibility-evidence-deep-dive.md`](https://github.com/iqbal-codes/labq-software-factory/blob/4ec6e86c1f96511fe5ffdebf2404edf0f34fcfcc/docs/research/eligibility-evidence-deep-dive.md). ## Answers and remaining proof

1. **Admission and dependencies.** `docs/agents/software-factory-workflow.md` requires an open, canonically `ready-for-agent` issue, no hold/exclusion label or active claim, and closed verifiable prerequisites. Native edges and textual declarations must agree. The prior source trace and synthetic workability probe show that pinned workability does not enforce canonical readiness and can consider a held issue with an absent prerequisite workable. The model picker is not proven to choose that particular issue; the demonstrated risk is that this deterministic precondition does not exclude it. PR continuation also needs equivalent policy. Planning records cannot be protected by UI presentation alone.
2. **Selection and launch binding.** `packages/contracts/src/operator.ts` accepts a specification, and `apps/engine-host/src/native.ts` forwards it to detached native `archon-loop`, not a verified issue identity. The pinned workflow declares no target input; the earlier synthetic declared-input check rejected `target`. Its picker emits the target, may write before claim, and the claim gates that selected target, not a separately admitted one. A board-level precheck or post-pick veto therefore does not prove prevention of unadmitted selection-side effects. [INFERENCE] The safe interim is to hold launches requiring that guarantee until an authorized design enforces fresh repo-scoped admission and binding before effects, claim/race revalidation, PR continuation and direct/scheduled bypass controls. The permissible integration seam and atomicity remain unproved; do not quietly fork or change the evaluator.
3. **Evidence.** `apps/engine-host/src/native.ts` derives `candidate_head` from the run's checkout baseline and returns fixed runtime PASS, holdout PASS, approved independent review and report availability. These are not authoritative verification. The pinned graph's subject/check/evidence/review records and `workflow get --json --verbose --events` are potential inputs, not proof of current-head attribution or independent principal: attempt/retry association, complete store semantics, principal provenance, live forge head and artifact existence all remain to be established. Different session identifiers or `context: fresh` alone do not prove independence. The pinned head-matched land path is a separate merge control; Factory requests `merge=approve`, not that auto-land path. Preserve evaluator independence and disclose only allowlisted metadata, never holdout contents.
4. **Repository scope.** `apps/backend/src/main.ts` constructs an unconfigured `IntakeService`; `apps/backend/src/intake.ts` defaults to the Factory repository, whereas host launch runs in `repoRoot`. [INFERENCE] A different product repository can therefore be evaluated against a different backlog; no cross-repository binding is established. A full owner/repository identity must be verified for issue, dependency, PR and execution context. Product configuration and conflict policy require an owner decision.
5. **Unknown versus absent.** `readLapDetail` suppresses `native_state_unavailable` and reports `lap_not_found`; the run listing is bounded to 100. Intake fetches a bounded list and its issue endpoint similarly reports missing entries as not found; missing prerequisites are held, including potentially closed ones outside that list. Inaccessible, truncated, stale or ambiguous data is not proof of nonexistence or of admission. Direct lookup and pagination/error semantics need explicit verification.
6. **Markdown reports.** Host report retrieval returns Markdown from candidate paths; backend `forwardToHost` parses every response as JSON, including the report route (`apps/backend/src/main.ts`), while the client expects text. Ordinary Markdown will fail that JSON parse; whether the candidate paths correspond to real native artifacts and whether the full proxy works after correction remain unproved. A contract must distinguish report unavailable, authoritative absence and transport failure without exposing private material.

## Additional safe offline checks

With `OPENROUTER_API_KEY` removed, Bun loaded the actual Factory `readLapEvidence` and `readLapDetail` functions and replaced `Bun.spawnSync` in-process with synthetic responses. A synthetic **failed** run with baseline `baseline-not-pr-head` returned verified/PASS, holdout PASS, approved/independent review and report available, attributing all to that baseline. A synthetic nonzero native-list response produced `lap_not_found`. Separately, `new Response('# Review\napproved').json()` raised `SyntaxError`, matching the backend's parsing operation. This is a direct function-level counterexample and a parsing probe, **not** an end-to-end host/backend/client test, a real run-store test, or evidence about actual holdout execution. No workflow was invoked, no holdout content was read, and no network transport was used by these checks. The Factory checkout had no `node_modules`; no Factory integration suite was run.

Earlier branch evidence records 28 passing pinned upstream input/serialization unit tests and a synthetic `target` rejection; those checks were not rerun here. They do not prove actual workflow execution, completeness of raw events, or reviewer independence.

## Proof required for an implementation handoff

- An authorized execution design and offline integration proof bind an explicitly scoped admitted issue/PR to the actual native selection, claim and first side effect, cover races, stale/missing dependencies, claims, Wayfinder planning records, PR continuation and every direct/scheduled entry point. Explicitly resolve text/native dependency conflicts and inaccessible state.
- Synthetic native-store fixtures and supported APIs establish complete run/invocation/attempt association and authoritative verification/review outputs for the same current PR head; prove reviewer principal independence, negative and missing evidence handling, fresh forge-head checking, and no builder self-approval. Preserve protected evaluator and holdout boundaries.
- Exercise cross-repository equal issue numbers, pagination and unreachable services; distinguish not found from unknown. Exercise actual host → backend → client report responses with synthetic Markdown, absent artifacts and JSON errors, without reading holdout contents.
- Obtain human decisions on the permitted integration seam, repository identity and unresolved policy choices before claiming the map's decision is complete. The proof above is implementation validation, not a claim that code was changed in this research.
