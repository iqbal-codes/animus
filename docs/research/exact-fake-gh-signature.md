# Issue 56: exact suite-generated fake `gh` signature

## Result

On this macOS host, the exact fake `gh` generated by the full boundary suite has an invalid signature and is killed before its fixture code runs. In a second full-suite run, re-signing the newly generated fake immediately after its build changed the result from **15 pass / 19 fail** to **34 pass / 0 fail**, with the same test assertions and safety controls. This is evidence that re-signing fixes this suite failure in this environment, not an explanation of why Bun produces the invalid signature or a product fix.

## Setup and controls

The source was the local pinned Archon cache at revision `5c4f5e484262185926b37b070457fabb9bfedae0`, confirmed with `git -C "$SOURCE" rev-parse HEAD`. The entire checkout, including dependencies, was copied with `cp -cR "$SOURCE" "$D/repo"` into `/tmp/issue56-exact.9hEzyM`; the shared engine was not modified. `D/bin` contained symlinks to the installed Bun and uv and a `gh` shell script that prints `BLOCKED_REAL_GH` and exits 125. The inherited PATH contained only that directory and `/usr/bin:/bin:/usr/sbin:/sbin`; suite-specific PATHs prepend the generated fake. `D/offline.sb` contained:

```scheme
(version 1)
(allow default)
(deny network*)
```

`sandbox-exec -p '(version 1)(allow default)(deny network*)' /usr/bin/true` exited 0. Both suite runs used this sandbox and `UV_OFFLINE=1`. No actual `gh`, network, live workflow, or holdout contents were used. These runs execute the test's local scripts and synthetic fixtures, not a live workflow. The blocker marker did not appear in either captured suite log; absence of the marker alone would not prove no invocation because child stderr can be captured by tests. The restricted PATH and network sandbox are the actual controls.

Environment: `Darwin arm64`; Bun `1.4.0`, revision `1.4.0+34cbb9a40`; uv `0.11.7 (9d177269e 2026-04-15 aarch64-apple-darwin)`.

## Instrumentation and commands

The sole source change was in the disposable copy, immediately after the suite's `bun build ... --compile --outfile` and `chmod` in `packages/workflows/src/defaults/factory-workflow-scripts.test.ts`. This preserves the exact generated executable before `afterAll` removes the temporary tree; a failed capture, signing, or verification fails the test setup. No fixtures, scripts, or assertions were changed:

```ts
const probe = Bun.spawnSync(['/bin/cp', fakeGh, process.env.PROBE_COPY!]);
if (probe.exitCode !== 0) throw new Error('capture failed');
if (process.env.PROBE_SIGN === '1') {
  const sign = Bun.spawnSync(['/usr/bin/codesign', '--force', '--sign', '-', fakeGh]);
  if (sign.exitCode !== 0) throw new Error(sign.stderr.toString());
  const verify = Bun.spawnSync(['/usr/bin/codesign', '--verify', '--verbose=2', fakeGh]);
  if (verify.exitCode !== 0) throw new Error(verify.stderr.toString());
}
```

Both runs used the same instrumented test and command, with only `PROBE_COPY` and `PROBE_SIGN` differing:

```sh
cd "$D/repo"
PATH="$D/bin:/usr/bin:/bin:/usr/sbin:/sbin" UV_OFFLINE=1 \
  PROBE_COPY="$D/baseline-gh" \
  /usr/bin/sandbox-exec -f "$D/offline.sb" "$D/bin/bun" test \
  packages/workflows/src/defaults/factory-workflow-scripts.test.ts

PATH="$D/bin:/usr/bin:/bin:/usr/sbin:/sbin" UV_OFFLINE=1 \
  PROBE_COPY="$D/resign-before-gh" PROBE_SIGN=1 \
  /usr/bin/sandbox-exec -f "$D/offline.sb" "$D/bin/bun" test \
  packages/workflows/src/defaults/factory-workflow-scripts.test.ts
```

## Exact artifact checks

```sh
/usr/bin/codesign --verify --verbose=2 "$D/baseline-gh"
/usr/bin/codesign --verify --verbose=2 "$D/resign-before-gh"
/usr/bin/shasum -a 256 "$D/baseline-gh" "$D/resign-before-gh"
```

Both verifications exited 1 with `invalid signature (code or signature have been modified)` and `In architecture: arm64`. The preserved pre-sign hashes were respectively `88c47d5f59abe4f07ea89cbc7f5949d6bd4cc5862fe3ae4b298ce673138e2d17` and `dad65cb65202276fd1e2297a6ddcceb909e5cd5362e18eb27f00c80a9053fe29`; the separately compiled outputs are not byte-identical. In the second run, the inline `codesign --verify` on the actual re-signed executable exited 0 before any assertions ran; otherwise setup would have thrown.

Directly executing the captured baseline fake under the same sandbox with `GH_LOG="$D/direct.log"` and arguments `pr view` returned 137 (`Killed: 9`), produced zero stdout and stderr bytes, and did not create the fake's log. The command was:

```sh
PATH="$D/bin:/usr/bin:/bin:/usr/sbin:/sbin" UV_OFFLINE=1 GH_LOG="$D/direct.log" \
  /usr/bin/sandbox-exec -f "$D/offline.sb" "$D/baseline-gh" pr view
```

## Interpretation and limits

The baseline's exact generated artifact is invalid and cannot reach its first logging statement. The re-sign experiment changes the signature of the executable used by the suite, after capturing its invalid pre-sign form, and the full unchanged assertions pass. This strengthens the earlier interpreted-wrapper probe: the separate minimal executable is no longer the only signature evidence. The comparison is one run per condition with separately built, non-identical binaries, not a repeated or randomized experiment; it does not establish cross-host reproducibility or isolate why the signatures are invalid. It does not validate real GitHub behavior, the separate loader/discovery failures, or issue 56's broader orchestration and merge guarantees.
