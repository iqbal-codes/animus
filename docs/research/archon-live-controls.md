### Ordering, replay and streaming

**Observed.** Archon run detail excludes high-volume provider rows and separately resolves CLI conversation identity ([API implementation](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/routes/api.ts#L4372-L4453)). The provider endpoint requires `step`, `attemptId` and nonnegative `afterSeq` together for a cursor ([schema](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/routes/schemas/workflow.schemas.ts#L213-L239)). Events are grouped by node in first-appearance order; attempts are in first-appearance order, each attempt ordered by sequence; sequence is contiguous from zero at emission, although asynchronous persistence can reorder writes. A cursor returns later sequence numbers of that attempt and all later attempts; an unknown attempt returns empty, not an error. Legacy rows have null attempt IDs and cannot be expressed as the API's nonempty-string cursor ([record and algorithms](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/workflows/src/schemas/provider-event.ts#L9-L96); [database reader](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/core/src/db/workflow-events.ts#L318-L388)). Unreadable rows are logged and skipped. This is not a global total-order cursor, and an empty response is not proof that an uncommitted attempt has no events. Keep a last **contiguous** sequence; reconcile gaps and legacy rows rather than advancing past a missing write.

**Observed.** SSE endpoints are `/api/stream/__dashboard__` and `/api/stream/:conversationId`, with heartbeats and disconnect cleanup ([routes](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/routes/api.ts#L3074-L3148)). The in-process bridge emits provider events to the conversation stream, not dashboard or bridged parent ([bridge](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/adapters/web/workflow-bridge.ts#L144-L146), [fan-out](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/adapters/web/workflow-bridge.ts#L351-L404)). A detached CLI process does not publish to the server's in-process emitter; the dashboard poller tails persisted lifecycle rows across processes, but not provider rows. It starts at boot, skips idle history, uses a timestamp boundary and ID deduplication, and has a 500-row drain cap ([poller](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/adapters/web/dashboard-event-poller.ts#L1-L19), [implementation](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/adapters/web/dashboard-event-poller.ts#L28-L153)). Conversation buffering is bounded and expires after 60 seconds, not durable replay ([transport](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/adapters/web/transport.ts#L24-L32), [registration](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/adapters/web/transport.ts#L67-L117)).

**[INFERENCE]** For Factory's detached CLI laps, use lifecycle SSE as a refetch hint only when the server shares the DB; poll/reconcile the persisted provider endpoint for transcripts, including while running. Do not promise conversation SSE receives the detached process's provider events. A subscribe/snapshot/reconcile design must tolerate duplicate, delayed and missing frames. The cited server surface is SSE, not evidence of a WebSocket control protocol. No WebSocket semantics were proven; a proposed WebSocket gateway would be a new Factory contract needing separate tests, not an Archon capability.

### Shared state and authorization

**Observed.** The CLI inherits the Factory host environment (`native.ts:138-141,311-314`). Archon's database selects PostgreSQL when `DATABASE_URL` is set; otherwise it opens `archon.db` under `ARCHON_HOME` ([connection](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/core/src/db/connection.ts#L1-L7), [selection](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/core/src/db/connection.ts#L28-L57)). **[INFERENCE]** CLI and server share state only if their effective DB configuration resolves to the same database and compatible host/runtime context; the launch code alone does not establish this. Confirm with an isolated shared database and synthetic records before exposing any control. Different `DATABASE_URL`, `ARCHON_HOME`, container mounts or hosts can separate state or make owner stopping impossible.

Archon's action authorization permits an operator or the run starter/admin, with only admin able to act on runs without a recorded starter ([policy](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/core/src/operations/run-authorization.ts#L4-L40)). Its API gate is conditional on web-auth configuration and trusts proxy identity only with appropriate proxy configuration ([API gate](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/routes/api.ts#L1918-L1933)). Factory's host requires a bearer token (`apps/engine-host/src/main.ts:24-32`), while its backend forwards that token (`apps/backend/src/main.ts:24-35`); both configurations restrict binding to loopback (`apps/backend/src/config.ts:7-12`, `apps/engine-host/src/config.ts:10-17`). There is no incoming user authorization check in the inspected Factory backend dispatcher (`apps/backend/src/main.ts:78-90`). **[INFERENCE]** Host bearer authentication is not per-user authorization for a future externally accessible UI; a gateway must authenticate and authorize reads and mutations itself and must not trust client-supplied identity headers.

### Cancellation, resume and steering

**Observed.** Native cancellation requires `running`: local-owner and eligible child paths are cooperative; for another process it verifies and stops the live owner before recording cancellation; failure to establish or stop the owner refuses without a state change. A container must also be confirmed stopped. A lost state-transition race is not reported as success ([operation](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/core/src/operations/workflow-operations.ts#L1210-L1297)). Descendant cancellation is best-effort with failure counts and a traversal cap; cleanup can warn and a parent waiting on an abandoned child can remain paused ([cascade and cleanup](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/core/src/operations/workflow-operations.ts#L802-L911), [API results](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/routes/api.ts#L3780-L3817)). Do not turn a cooperative acknowledgement, refusal, or cleanup warning into a claim that every process and resource has stopped. Paused or failed runs use abandon rather than cancel; this is a different operation.

**Observed.** Resume accepts failed/paused states and server handling has a headless path for CLI-origin runs; dispatch success is not workflow completion ([resume validation](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/core/src/operations/workflow-operations.ts#L938-L952), [API](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/routes/api.ts#L3819-L3892)). Native `respond` selects a declared gate decision and can include feedback and expected node/pause identity ([schema](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/routes/schemas/workflow.schemas.ts#L265-L276)); signaling targets an exact awaited event ([route](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/routes/api.ts#L3894-L3919)). These are constrained authored interaction points, not demonstrated arbitrary injection into a running lap. Whether and where this specific loop reaches such points, and stale-gate behavior in its exact graph, require further verification.

Factory's `pause` writes a PAUSE file and launch checks it before spawning (`apps/engine-host/src/native.ts:246-252,369-405`); `docs/agents/software-factory-workflow.md` explicitly says it does not stop manual runs, native wakes, or work already in flight. It is not an in-flight pause or integration freeze.

### Security and holdouts

**Observed.** Factory policy reserves holdout scenario reading for writer/verifier agents (`factory/WORKFLOW_POLICY.md:23-28`), and provider event envelopes retain the provider object unchanged ([schema](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/workflows/src/schemas/provider-event.ts#L4-L21)). Provider events can include tool output ([bridge comment](https://github.com/coleam00/Archon/blob/5c4f5e484262185926b37b070457fabb9bfedae0/packages/server/src/adapters/web/workflow-bridge.ts#L367-L374)). **[INFERENCE]** Raw transcripts, replay responses, errors and gate feedback must be treated as potentially containing secrets and holdout material; do not expose them to ordinary operators merely because a stream exists. Require a verified allowlist/projection and access policy across live, replay, logs, and errors; fail closed when safe classification cannot be established. No general redaction guarantee was proven by this inspection.

## Recommended seam and proof still required

**[INFERENCE]** Keep Archon as lifecycle and decision owner. A Factory adapter should expose a restricted, authorized run view using native run detail and per-step provider replay, with dashboard SSE only as a hint, and separately expose only documented owner-checked actions and actual pending gate decisions. Preserve error, partial-cleanup and stale-state results. Do not implement arbitrary pause/steering or WebSocket claims without an explicit native contract and behavioral proof. Avoid copying holdout text or credentials into projections.

Required offline proofs before implementation/claim: (1) isolated SQLite shared versus separate `ARCHON_HOME` and database identity; (2) synthetic detached writer plus server poller showing lifecycle but not provider SSE, plus REST recovery; (3) out-of-order writes, gaps, unknown cursor, later attempts, legacy rows, reconnect and duplicate reconciliation; (4) wrong user/admin/operator, disabled auth and proxy-header boundary; (5) cancel owner alive/dead/unreachable, child tree, stop failure, concurrent completion, container cleanup and paused-parent outcomes; (6) authored gate decision, stale pause identity and headless resume; (7) transcript and error filtering against synthetic secrets and synthetic holdout-like data. No live workflow run is authorized or needed for these synthetic tests.
