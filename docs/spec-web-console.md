# Spec: Operasikan Software Factory multi-repository melalui web console local-first

Tanggal: 2026-10-28  
Status: **Implementation-Ready Specification** (seluruh open questions Q1–Q7 telah diselesaikan via `/factory-grill`).  
Target repository: `iqbal-codes/labq-software-factory`  
Sumber: [Arsitektur Web Console Software Factory](https://github.com/iqbal-codes/labq-software-factory/issues/46), seluruh 11 child issue beserta komentar resolusinya, serta hasil grill Q1–Q7.  
Baseline source: `5fa30a37748d0acde86a6fc6c0fc3ba49d5e8105`.  
Usulan publikasi: parent spec baru dengan label `needs-info`, setelah persetujuan operator. Bukan `ready-for-agent`; bukan membuka kembali map.  
Otorisasi sesi ini: sintesis dan pembaruan spesifikasi lokal. Tidak mencakup publikasi, admission, launch, perubahan engine/evaluator, merge, promotion, deployment, atau penghapusan data/kode.

## Source and problem

Operator memerlukan satu console untuk mendaftarkan beberapa repository GitHub, menyiapkan backlog terstruktur, menjalankan pekerjaan yang benar-benar diizinkan, mengamati proses dan evidence, serta mengendalikan approval dan delivery tanpa berpindah ke shell untuk setiap operasi. Scope project harus tetap benar sepanjang alur, termasuk saat beberapa tab membuka project berbeda.

Map telah menyelesaikan arah arsitektur, bukan implementasinya. Catatan penutupan map dan child issue tidak membuktikan kapabilitas pinned engine sudah aman. Resolusi riset [live events dan run controls](https://github.com/iqbal-codes/labq-software-factory/issues/55#issuecomment-6461315841), [one-final-PR delivery](https://github.com/iqbal-codes/labq-software-factory/issues/56#issuecomment-6460939033), dan [eligibility/evidence integrity](https://github.com/iqbal-codes/labq-software-factory/issues/57#issuecomment-6461209829) secara eksplisit menyatakan temuan negatif atau belum terbukti. Kewajiban pembuktiannya dibawa ke spec ini, bukan dianggap selesai karena riset ditutup.

Research note pada commit lama masih menyebut tiket terbuka. Untuk disposisi planning, komentar resolusi terakhir adalah sumber terkini; batas teknis dan hasil probe pada note tetap berlaku. Hasil probe tersebut adalah bukti historis, bukan pengujian ulang sesi spec ini.

### Hubungan dengan pekerjaan sebelumnya

- [TypeScript/Bun monorepo with Vite+ and preserved Archon execution](https://github.com/iqbal-codes/labq-software-factory/issues/27) adalah migrasi baseline yang sudah ditutup. Spec ini memperluas produk dan memperbaiki kontrak yang terbukti tidak terpenuhi; tidak mengulang migrasi bahasa atau menganggap seluruh klaim spec lama telah terbukti.
- [Add engine-host version metadata helper in contracts](https://github.com/iqbal-codes/labq-software-factory/issues/44) masih terbuka. Helper versi itu bukan bukti release kompatibel atau prerequisite otomatis spec ini. Kontrak ekspor root pada tiket tersebut harus direkonsiliasi dengan keputusan pemisahan operator/host jika pelaksanaannya bersinggungan; draft ini tidak mengubah tiket itu.
- Dokumen desain lama bukan otoritas bila bertentangan dengan keputusan map: label `factory:*`, asumsi `target` pada loop, PAUSE sebagai freeze, pembatasan perencanaan hanya di luar aplikasi, per-ticket PR, dan larangan mutlak auto-merge/deploy tidak boleh dipulihkan dari dokumen lama. Policy otomatis yang secara terpisah disetujui tetap tunduk pada gates.

## Outcome

Satu aplikasi single-host, single-tenant, local-first memungkinkan operator mengelola project GitHub yang terisolasi melalui aksi terstruktur dari intake spec/backlog sampai delivery. Web dan backend tersedia pada satu origin localhost; engine-host privat menjadi jembatan ke pinned Archon. Instalasi dapat dibuka pada jaringan privat hanya setelah konfigurasi akses dan identitas operator yang terautentikasi dibuktikan.

Spec dengan subtiket menghasilkan tepat satu final PR dari kandidat terintegrasi. Standalone ticket menghasilkan satu PR sendiri. Operator dapat membiarkan eksekusi yang telah diotorisasi berjalan unattended, tetapi setiap gate, batas izin, dan policy repository tetap berlaku. UI menunjukkan sumber, freshness, keterbatasan, dan efek parsial secara jujur.

Kapabilitas yang belum terbukti harus ditahan. Menampilkan `unsupported` atau `unknown` memenuhi kewajiban kejujuran untuk kapabilitas tersebut, tetapi **tidak menggantikan outcome wajib** seperti admission aman, isolasi project, dan final-candidate delivery. Jika seam engine yang diizinkan tidak dapat memenuhi outcome, spec tetap blocked dan memerlukan keputusan operator, bukan pengurangan scope diam-diam.

## Invariants

1. **Satu pemilik kebenaran.** GitHub memiliki repository/issues/PR dan keadaan forge; Archon memiliki execution/workflow state. Console memiliki registry, konfigurasi non-secret, command ledger, dan koordinasi delivery spec yang disepakati. Projection/cache dapat dibangun ulang dan tidak menggantikan authority asal.
2. **Scope eksplisit sampai efek.** Query, command, subscription, run, evidence, approval, schedule, dan promotion project-spesifik terikat pada project ID dan resource yang diverifikasi. Scope hilang/tidak dikenal/mismatch ditolak tanpa fallback ke CWD, project terakhir, atau repo default.
3. **Admission mendahului efek eksekusi.** Planning record, issue yang held/excluded, target yang tidak terverifikasi, dan prerequisite yang belum terpenuhi tidak boleh menghasilkan selection/claim/execution side effect melalui jalur langsung, scheduled, continuation, atau koordinasi spec. Label UI dan prompt bukan enforcement boundary.
4. **Izin terpisah.** Publikasi, admission, launch, approval, merge, promotion, dan deployment adalah izin berbeda. Auto-merge dan auto-deploy merupakan policy project independen. Network membership, accepted request, atau gate historis tidak memberikan kewenangan tambahan.
5. **Candidate-bound evidence.** Runtime checks, independent review, dan keputusan landing berlaku untuk kandidat yang sama beserta base/merge tree yang relevan. Evidence stale, tidak lengkap, tidak independen, atau tidak terverifikasi menahan readiness/merge. Builder tidak mengesahkan sendiri hasilnya.
6. **Rahasia dan evaluator terlindungi.** Credentials, private holdout, dan raw privileged data tidak masuk browser, console DB, command history, log, report, atau projection operator. Ordinary tests tidak boleh menggantikan independent evaluation. Implementasi tidak boleh melemahkan evaluator/governance atau membuat fork privat workflow untuk melewati batas.
7. **Efek eksternal bukan transaksi tunggal.** Persisted request, acknowledgement, completion, dan verified outcome berbeda. Timeout tidak membuktikan tidak ada efek. Rekonsiliasi mendahului retry konsekuensial; tidak ada klaim exactly-once lintas GitHub/Archon.
8. **Clean cutover per fitur.** Setiap perubahan kontrak memigrasikan seluruh caller fitur terkait secara atomik, tanpa shim/alias atau implementasi paralel permanen. Fitur yang belum dimigrasikan tetap dinyatakan legacy aktif, bukan diklaim sudah mengikuti arsitektur baru.

## Acceptance criteria

Kriteria berikut mendefinisikan target kontrak executable.

### Project, data, dan recovery

- [ ] **AC01: Registrasi terverifikasi.** Operator dapat memilih checkout Git lokal, clone repository GitHub, atau membuat repository GitHub beserta checkout. Ketiga jalur memverifikasi GitHub host + stable repository ID, checkout, dan pilihan operator sebelum project aktif. Satu repository hanya memiliki satu project aktif per instalasi. Rename/transfer dengan ID sama mempertahankan identitas; alamat yang belum diverifikasi tidak dianggap setara. Uji ketiga jalur, duplikasi, offline, dan mismatch.
- [ ] **AC02: Efek parsial registrasi dan retarget.** Create mengonfirmasi owner, nama, visibility, dan lokasi checkout. Repository yang sudah dibuat atau folder clone parsial dilaporkan bila tahap selanjutnya gagal; tidak dihapus otomatis. Checkout hilang/berubah identitas menahan operasi terkait. Pergantian checkout untuk repository sama membutuhkan pilihan/validasi eksplisit; repository berbeda membutuhkan project baru. Uji kegagalan setelah efek dan retarget salah repo.
- [ ] **AC03: Isolasi lintas project.** Dua project dengan nomor issue/run serupa tidak saling memengaruhi melalui query, command, evidence/report, schedule, controls, promotion, atau subscription. Tab A tetap menarget A ketika tab lain membuka B. Akses run B melalui A ditolak. Unknown/missing scope menghasilkan classified refusal tanpa efek. Agregat menampilkan provenance project dan membuka detail berscope benar. Buktikan pada backend dan host, tidak hanya browser.
- [ ] **AC04: Registry dan command durable (WAL SQLite & Single Writer).** SQLite milik console berada pada installation state directory terisolasi (`~/.factory/state/console.db` berizin 0700). Mode WAL aktif dengan single-writer connection di backend dan multiple reader connections. Project ID, hubungan repository/checkout, konfigurasi non-secret, dan command records bertahan setelah restart. Setiap command konsekuensial yang memerlukan provenance/reconciliation memiliki request identity, requester/automation source, scope, target, waktu, dan initial state yang durable **sebelum dispatch**. Kegagalan write menolak dispatch; acknowledgement/outcome disimpan terpisah. Uji restart, concurrent requests, dan kegagalan storage.
- [ ] **AC05: Rekonsiliasi dan data authority.** Restart/restore merekonsiliasi command `dispatched` yang belum selesai terhadap engine-host / GitHub tanpa blind resend. Run eksternal hanya diberi project jika relasinya terverifikasi; run yang belum teratribusi tidak menerima project-scoped action. Cache yang dihapus dapat dibangun ulang tanpa menghapus registry/history/engine/forge state. Data stale menampilkan source dan observation time; unavailable, absent, malformed, dan incomplete/truncated dibedakan. Uji ambiguous acknowledgement, external contradiction, pagination, dan authority unavailable.
- [ ] **AC06: Removal, backup, dan snapshot migrasi aman.** Removal registrasi ditolak selama ada run aktif; setelah diizinkan menyisakan tombstone dan atribusi command, tidak menghapus repository/checkout/worktree/evidence. Command metadata/evidence links dipertahankan tanpa pruning otomatis, khususnya unresolved commands. Backup konsisten via SQLite VACUUM INTO menyertakan schema/version compatibility; restore memerlukan konfirmasi, revalidasi checkout/identitas, dan rekonsiliasi. Pre-migration snapshot otomatis dibuat sebelum schema upgrade; migration failure menjaga data dan menahan dispatch.

### Intake, execution, dan delivery

- [ ] **AC07: Intake terstruktur.** Operator dapat membaca, meninjau, memublikasikan/memperbarui spec dan tiket serta menilai/mengubah readiness melalui aksi terstruktur, tanpa chatbot atau shell. Preview menampilkan target repo, perubahan, alasan admission/hold/exclusion, dan efek label. Publikasi/readiness membutuhkan izin masing-masing; parent spec dan wayfinder tetap planning-only, bukan executable work.
- [ ] **AC08: Admission dan exact-target enforcement.** Sebelum side effect, direct/scheduled/continuation/spec-dispatch paths memverifikasi target repo/issue/PR, executable contract, canonical labels, prerequisites, active claim, dan state terkini. `wontfix` mengecualikan; `needs-info`, `ready-for-human`, `needs-triage`, unlabeled/unknown-only, serta unresolved/unverifiable dependency menahan. Legacy `factory:*` tidak memberi authority. Subtiket yang bergantung pada tiket lain divalidasi status integrasi lokalnya (`integrated_to_branch`). Issue yang benar-benar dijalankan harus identik dengan target yang diadmit; race atau unavailable state menolak/menahan.
- [ ] **AC09: Koordinasi spec via targeted primitives.** Factory mengoordinasikan admitted child selection/claims, explicit target binding, dan serialized integration; Archon menjalankan targeted work melalui primitif eksekusi individual (`archon-implement` dengan kontrak yang dibekukan per subtiket), bukan loop picker umum yang tidak terikat. Membership/dependencies/contract snapshot dan ownership tetap dapat direkonsiliasi setelah drift/restart. Competing coordinators tidak mengerjakan/mengintegrasikan child yang sama secara tidak sah. Completion status saja bukan authored-green evidence.
- [ ] **AC10: Isolated work dan satu final PR.** Subtiket berjalan pada checkout/worktree/branch terisolasi yang repo, expected starting SHA, dan exclusive writer-nya dibuktikan sebelum node pertama serta selama eksekusi. Hasil yang memenuhi kontrak diintegrasikan terserialisasi ke integration branch lokal (`integrated_to_branch`), membuka dependensi untuk subtiket berikutnya tanpa menutup isu di GitHub prematur. Conflict/drift/restart menahan integrasi tanpa kehilangan atribusi. Tepat satu final PR dibuat untuk spec dan tidak ada PR per subtiket; standalone ticket menghasilkan satu PR.
- [ ] **AC11: Evidence dan landing kandidat final.** Subtiket menjalankan checks proporsional terhadap kontraknya, tanpa kewajiban black-box app check pada masing-masing isolated branch. Final integrated spec candidate pada branch integrasi, dan final candidate standalone ticket, menerima applicable independent black-box check serta review. Final PR boleh dibuat sebelum check itu selesai, tetapi readiness/merge tetap held. Evidence mengikat trusted spec, PR, head, base/merge tree relevan, runtime/setup, dan trusted producer; perubahan material menginvalidasi evidence. Landing guard mencegah merge jika kandidat berbeda dari pohon yang diverifikasi.
- [ ] **AC12: Tiered action matrix dan freshness.** Backend dan host memvalidasi action, project, resource, gate, expected state/candidate, dan authorization kembali saat eksekusi. Read-only/telemetry memakai TTL pendek (30-60 detik). Reversible controls (pause/brake) memerlukan konfirmasi 1-klik. Aksi konsekuensial (Launch, Cancel, Approve Gate, Prepare Promotion PR, Merge/Deploy) mewajibkan modal dialog konfirmasi yang menampilkan target branch, candidate SHA, dan issue numbers, serta **live freshness check ≤10 detik**. Jika terjadi drift (SHA/prasyarat berubah), aksi ditolak tertutup (fail closed). Auto-merge dan auto-deploy tetap policy independen.
- [ ] **AC13: Command outcome jujur.** Operator dapat membedakan rejected, accepted/acknowledged, running/waiting, succeeded, failed, partial, dan unknown beserta provenance. Duplicate request dikenali sejauh seam mendukung, tanpa menjanjikan exactly-once. Timeout setelah PR dibuat menampilkan unknown/partial yang kemudian direkonsiliasi; tidak membuat duplikat otomatis. Kegagalan prerequisite freshness menolak efek dengan alasan spesifik.
- [ ] **AC14: Controls dan schedule berscope.** Schedule pause, project/global launch brake, per-run cancellation, process termination, serta native authored gate/resume tidak diperlakukan setara. Global brake mencegah launch seluruh instalasi tanpa menghapus project brake; unbrake global tidak membuka brake project. Brake/pause tidak mengklaim run aktif berhenti atau candidate frozen. Direct/scheduled paths menegakkan applicable verified brake; required brake unknown menahan launch. Per-run control hanya available sesudah pembuktian scope, authorization, native response, dan efek/cleanup; unsupported bukan successful no-op.
- [ ] **AC15: Approval, promotion, dan deployment.** Approval menyebut gate/project/target/candidate tertentu dan diverifikasi dengan current engine/forge state, bukan historical waiting state. Promotion menampilkan source/target/candidate dan prerequisite, serta melaporkan PR creation dan brake/freeze sebagai efek terpisah. PR created tidak berarti approved, merged, frozen, atau deployed. Merge dan deployment memerlukan bukti/izin masing-masing; release-complete hanya jika seluruh policy-required stages terverifikasi. Uji overlap, stale candidate, no changes, dan PR-created/brake-failed tanpa rollback/retry otomatis.
- [ ] **AC16: Evidence/report aman end-to-end.** Host → backend → `@labq/client` → web menyajikan hanya metadata/artifact terverifikasi dan allowlisted, termasuk report Markdown dengan transport/content type yang benar. Failed/missing/stale verification tidak menghasilkan PASS/approved/report-available rekaan. API unavailable tidak dipetakan sebagai not-found. Synthetic secret/holdout-like payload tidak lolos melalui response, report, error, log, maupun live/replay.

### Operator UI dan transport

- [ ] **AC17: Frontend dan navigator berscope.** Frontend dimigrasikan bersih ke React/TypeScript pada Vite toolchain yang disepakati, TanStack Router/Query/Form, dan Zod; semua operator operation melalui `@labq/client` dan schema operator. Routes/query keys membawa project/resource identity. Sidebar bounded/searchable menampilkan satu row per spec (dengan verified integrated progress misal `2/10`) dan standalone issue, tanpa nested ticket submenu; planning record ditandai. Spec detail memuat visualisasi DAG child/dependencies dan status integrasi branch.
- [ ] **AC18: Live observation dan recovery.** Connection manager WebSocket yang project/lap-scoped memakai bounded buffer, reconnect, deduplication dan gap signaling; snapshots/query reconciliation membentuk initial/recovered truth. Lifecycle events adalah invalidation hints, bukan monotonic state log atau bukti completeness. Duplicate/out-of-order/late events tidak mengubah completed menjadi running tanpa current authoritative evidence. Reconnect tidak melakukan blind retry pada command konsekuensial.
- [ ] **AC19: UI primitives shadcn & visual tokens x.ai.** Desain mengadopsi visual tokens dari brief/x.ai (dark high-contrast `#0A0A0A`, container `#1A1A1A`, border `#1F2228`, teks kontras tinggi, aksen oranye `#FF6308`, dan font GeistMono/Sans), namun seluruh komponen interaktif menggunakan **shadcn/ui primitives murni** (Base UI, Dialog, Forms, Tabs, Buttons, Badges, Table) tanpa fake terminal windows atau fake marketing chrome. Long logs virtualized, states (loading, empty, error, stale, disconnected) jujur tanpa demo data. Keyboard accessible, visible focus, dan lolos uji kontras WCAG AA.

### Arsitektur, instalasi, harness, dan distribusi

- [ ] **AC20: Boundary executable.** Workspace web/backend/engine-host/contracts/client tetap dipertahankan dengan feature-based small explicit public interfaces. Feature callers tidak mengimpor internal fitur lain atau storage pemilik lain. Browser/client tidak mengimpor app/server/host privilege; contracts tidak bergantung pada internal app. Operator/host schema entrypoints terpisah, types diturunkan dari runtime schemas, tanpa root export-all. Deliberate forbidden imports membuat architecture check gagal; allowed feature calls tetap lolos.
- [ ] **AC21: Satu instalasi, dua proses privat.** Launcher/configuration/start/stop/recovery mengoperasikan backend dan engine-host sebagai satu aplikasi, dengan static web/API satu localhost origin default. Engine-host hanya diakses backend melalui validated private interface, bukan endpoint browser atau arbitrary engine/shell dispatch. Partial startup/shutdown failure dilaporkan per proses. Shutdown aplikasi tidak disamakan dengan cancellation seluruh detached native work.
- [ ] **AC22: Akses privat dan kredensial terlindungi.** Localhost loopback bind default (`127.0.0.1`). File local session secret berizin `0600`. Akses privat/Tailscale dinonaktifkan secara default; jika diaktifkan (`FACTORY_REMOTE_ACCESS=true`), mewajibkan token otentikasi operator statis/passphrase, bind IP privat, dan proteksi CSRF ketat. Kredensial forge (GitHub Token / API keys) disimpan di server-side protected environment / OS credential manager, tidak pernah di SQLite console, browser bundle/localStorage, maupun API telemetry publik.
- [ ] **AC23: Ordinary offline verification.** Bun test mencakup backend/persistence/contracts/host integration dengan in-memory SQLite dan synthetic forge/engine transports. Vitest/React Testing Library menguji frontend/component state; Playwright menguji critical single-origin operator journeys dengan mock backend. Ordinary suites tidak memakai live external network atau credentials; loopback fixtures boleh untuk transport/process tests. Passing mocks bukan independent runtime evidence.
- [ ] **AC24: CI gagal tertutup.** GitHub Actions memakai qualified locked Bun toolchain dan frozen dependency install. Gates berurutan: static lint/format/architecture; typecheck/unit/contract/offline integration verification; frontend build dan backend/host packaging. Required browser verification dari AC23 dihubungkan ke pipeline secara eksplisit. Deliberate failure tiap gate menghentikan kandidat berikutnya; artifact candidate tidak dipublikasikan sebelum semua required gates lulus.
- [ ] **AC25: Unified release dan recovery.** Release bundle memiliki immutable SemVer + Git SHA, web/backend/engine-host versi sama, frontend disajikan Bun backend launcher, dan engine pin/schema compatibility tercatat serta diperiksa. Instalasi/update berada pada self-contained application directory terpisah dari managed project state. Sebelum schema upgrade dibuat consistent SQLite snapshot (`console.db.pre-vX.X.X.bak`); kegagalan menjaga data/dispatch closed. Rollback mengembalikan previous binary release dan restore snapshot database pra-migrasi dengan konfirmasi eksplisit operator. Matriks target: macOS (darwin-arm64, darwin-x64) dan Linux (linux-x64, linux-arm64).
- [ ] **AC26: Cutover dan bukti selaras.** Seluruh caller fitur yang berubah, contract/client, scripts/configuration, dan active guidance memakai pola/command TypeScript yang benar; legacy Python instruction yang masih aktif direkonsiliasi. Artifact evidence mencatat source spec/AC, scenario/command, result PASS/FAIL/BLOCKED/NOT RUN, candidate/head/base relevan, dan artifact location. Rerun checks terdampak setelah candidate/base berubah.

## Boundary

### Termasuk

Semua outcome AC01–AC26: project registration/isolation; structured intake dan commands; console persistence/recovery (SQLite WAL); Factory spec coordination via targeted primitives (`archon-implement`); evidence/final delivery gates; React operator frontend dengan shadcn primitives dan x.ai tokens; private installation/access; executable architecture/testing; serta distribution/update/rollback aplikasi dengan snapshot.

Pekerjaan korektif admission/evidence dari riset termasuk requirement penyelesaian. Migrasi kontrak per fitur membawa seluruh caller yang diperlukan.

### Tidak termasuk

- Public multi-tenant SaaS, billing, marketplace plugin, atau multi-host worker/fleet orchestration.
- Conversational chatbot, interactive shell, unmanaged AI runner, replacement workflow state machine/scheduler, atau private fork workflow Archon.
- Local Markdown tracker atau operasi tanpa GitHub.
- Generic CI/CD platform pengganti forge; mobile/desktop client baru.
- Pelemahan evaluator, akses private holdout, self-approval builder, atau aplikasi mengubah protected governance agar gate lolos.
- Penghapusan permanen console records, repository, checkout, worktree, atau evidence sebagai efek removal registrasi.
- Publikasi release, provisioning, branch-protection changes, launch, merge, promotion, atau deploy sebagai efek persetujuan dokumen spec.

## Verification

### Public seams

Permukaan utama adalah operator API melalui `@labq/client` terhadap backend, dengan request/response/error schemas yang sama dengan web. Uji observable results, refusals, scope, provenance, dan state transitions, bukan constructor wiring atau jumlah folder.

Supporting seams:
1. **Private host/native adapter + proses nyata:** explicit target, pre-node checkout identity/ownership, native acknowledgement/reconciliation, backend/host lifetime, controls, dan cleanup. Synthetic native subprocess/forge adapters digunakan untuk ordinary tests; actual configured native behavior adalah qualification terpisah.
2. **SQLite persistence:** transaksi command-before-dispatch, WAL concurrency, restart/crash ambiguity, corruption/migration/backup/restore. Gunakan in-memory DB untuk isolasi unit/integration dan temporary real file untuk durability/restart proof.
3. **Browser single-origin:** Playwright untuk project switching/multiple tabs, forms/confirmation modal, sidebar/spec progress, evidence/report, connection recovery, dan keyboard/focus journeys. Mock backend membuktikan UI behavior, bukan live native capability.
4. **Architecture/CI/release commands:** negative forbidden-import/type/test controls, gated packaging, clean installation, migration snapshot/rollback.
5. **Independent final-candidate verification:** current trusted producer/review provenance, black-box app evaluation, head/base/tree binding, dan enforced landing.
